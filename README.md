# 1. Introduction

This project was developed for the PLSQL Assignment One - Sunrise Supermarket.

The purpose of the project is to create a relational database for Sunrise Supermarket and use SQL queries to analyze customer purchases, products, orders, and sales revenue.

The database contains four main tables:

- `CUSTOMERS`
- `PRODUCTS`
- `ORDERS`
- `ORDER_ITEMS`

The project demonstrates practical use of relational database concepts, SQL joins, aggregate functions, Common Table Expressions (CTEs), subqueries, and window functions.

The analysis provides useful information about customer purchasing behavior, order history, revenue, and the relationship between customers and products.

# 2. Business Scenario

Sunrise Supermarket sells different products to customers.

Customers can place one or more orders, and every order can contain several products. Each product has a name, category, and price.

The supermarket needs a database to store this information and perform sales analysis.

The database can help answer questions such as:

1. Which customers placed orders?
2. What products were purchased?
3. Which customers have not placed orders?
4. Which customers spend more than the average?
5. How are customers ranked according to their spending?
6. How many orders has each customer made?
7. What revenue was generated by each order?
8. What is the running total of revenue?
9. How many days are there between a customer's orders?

This information can help Sunrise Supermarket understand its customers and sales activity.

12. Common Table Expression (CTE)
Customers Spending More Than Average
SQL Query
WITH customer_spending AS (
    SELECT
        c.customer_id,
        c.customer_name,
        SUM(oi.quantity * p.price) AS total_spend
    FROM customers c
    INNER JOIN orders o
        ON c.customer_id = o.customer_id
    INNER JOIN order_items oi
        ON o.order_id = oi.order_id
    INNER JOIN products p
        ON oi.product_id = p.product_id
    GROUP BY
        c.customer_id,
        c.customer_name
)
SELECT
    customer_id,
    customer_name,
    total_spend
FROM customer_spending
WHERE total_spend > (
    SELECT AVG(total_spend)
    FROM customer_spending
)
ORDER BY total_spend DESC;
Explanation

The CTE is called customer_spending.

It calculates the total amount spent by each customer.

The total spending is calculated using:
SUM(oi.quantity * p.price)
The main query then compares each customer's spending with the average spending.

Only customers whose spending is greater than the average are returned.

14. Window Function 1: Customer Spending Rank
SQL Query
SELECT
    customer_id,
    customer_name,
    total_spend,
    RANK() OVER (ORDER BY total_spend DESC) AS spending_rank
FROM (
    SELECT
        c.customer_id,
        c.customer_name,
        SUM(oi.quantity * p.price) AS total_spend
    FROM customers c
    INNER JOIN orders o
        ON c.customer_id = o.customer_id
    INNER JOIN order_items oi
        ON o.order_id = oi.order_id
    INNER JOIN products p
        ON oi.product_id = p.product_id
    GROUP BY
        c.customer_id,
        c.customer_name
)
ORDER BY spending_rank;
Explanation

The inner query calculates the total spending for each customer.

The RANK() function then assigns a rank based on total spending in descending order.

Explanation

The ROW_NUMBER() function assigns a sequential number to each order.

The:PARTITION BY customer_id

17. Window Function 4: Days Between Customer Orders
SQL Query

WITH customer_orders AS (
    SELECT
        customer_id,
        order_id,
        order_date,
        LAG(order_date) OVER (
            PARTITION BY customer_id
            ORDER BY order_date
        ) AS previous_order_date
    FROM orders
)
SELECT
    customer_id,
    order_id,
    order_date,
    previous_order_date,
    order_date - previous_order_date AS days_between_orders
FROM customer_orders
WHERE previous_order_date IS NOT NULL
ORDER BY customer_id, order_date;

Explanation

The LAG() window function retrieves the previous order date for each customer.

The query then subtracts the previous order date from the current order date.

This produces the number of days between two consecutive orders made by the same customer.

20. Challenges Encountered and Solutions
Challenge 1: Foreign Key Relationships

The database contains relationships between customers, orders, products, and order items.

Solution

The tables were created in the correct dependency order.

The parent tables were created first:

CUSTOMERS
PRODUCTS

The dependent tables were then created:

ORDERS
ORDER_ITEMS

This allowed the foreign keys to reference existing tables.

Challenge 2: Inserting Related Data

Orders require valid customer IDs.

Order items require valid order IDs and product IDs.

Solution

The data was inserted in the following order:

Customers
Products
Orders
Order Items

This maintained referential integrity.

Challenge 3: Calculating Customer Spending

Customer spending requires data from multiple tables.

Solution

The tables were connected using multiple INNER JOIN statements.

The calculation was performed using:

SUM(quantity * price)

This produced the total spending for each customer.

Challenge 4: Finding Customers Without Orders

An INNER JOIN would not display customers who have no orders.

Solution

A LEFT JOIN was used.

This allowed all customers to be displayed, including customers with no matching order.

Challenge 5: Finding the Previous Order

Comparing a customer's current order with their previous order requires accessing another row in the same customer group.

Solution

The LAG() window function was used:

LAG(order_date) OVER (
    PARTITION BY customer_id
    ORDER BY order_date
)

This returns the previous order date for each customer.
